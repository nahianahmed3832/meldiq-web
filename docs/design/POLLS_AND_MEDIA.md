# Poll results and image navigation

Poll cards use the community theme's accent, restrained progress fills, explicit count + percentage columns and a clearly separated visibility control. Percentages count people, not selections: multiple answers can sum above 100%. Results are available without voting, filter by answer and page through voters. Empty, expired and closed states remain readable. Creators can schedule closing after 1 hour, 24 hours, 3 days or 7 days; early closure has confirmation. Voters can change or remove a ballot while voting remains open. Duplicate normalized answers are rejected.

“Vote anonymously” means **hide your name in poll results**, as the adjacent helper says. `anonymous` is optional metadata on the existing attributable vote control; sender IDs remain in transport/storage to support deduplication and vote changes. This is not unlinkable or cryptographic anonymity. Updated web clients render hidden ballots as Anonymous voter without requesting their name/photo or putting their IDs in result records. Older clients may ignore this new metadata. An omitted flag preserves a previous hidden-name preference. Imports keep the flag; forwarding starts a new poll without ballots or ballot visibility metadata.

The full-screen viewer uses a bounded, measured scrolling viewport and explicit image dimensions to preserve the complete aspect ratio. Fit image, Fit width, actual size, zoom buttons, double-click, +/−/0/1 shortcuts, mouse dragging and touch scrolling make long screenshots readable. Previous/next buttons, arrow keys and a short thumbnail strip move through the loaded conversation's media, across message boundaries. Selection uses attachment IDs so arrivals cannot shift the selected image. Caption, sender and reactions follow the selected message. Escape closes the viewer, focus returns to its opener and Tab stays within the overlay. Failed files can be retried or downloaded. Media gallery navigation respects selection mode and automatic photo download preferences.

Automatic photo optimization preserves originals whose aspect ratio is at least 3:1 in either direction. This prevents the previous longest-edge resize from turning tall screenshot text into tiny pixels. Earlier uploads already downscaled cannot regain lost source detail. Other photos retain automatic optimization, animated files remain intact and attachment encryption/storage paths are unchanged.

Reference research: [Discord's Polls FAQ](https://support.discord.com/hc/en-us/articles/22163184112407-Polls-FAQ) describes durations, multiple answers, viewing results and changing votes. This implementation adds per-ballot name visibility requested by the owner. [Discord's February 2026 patch notes](https://discord.com/blog/discord-patch-notes-february-4-2026) identify image gallery zoom and desktop media viewer polish as active usability concerns. The implementation uses Meldiq's existing overlay, typography, colors and icon system.

Validation uses the actual Webpack production export with its production CSP, disposable local accounts/API and normal email onboarding, in Chromium and WebKit. No production messages, accounts or poll votes are created by verification.
