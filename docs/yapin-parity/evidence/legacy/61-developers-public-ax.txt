								572 heading How it works, Value: 2
									573 text How it works
								574 text Yapin’ keeps every event for your bot for a day: new messages in its servers, joins, leaves, reactions, button clicks, voice joins and leaves, tests. Your bot asks
								575 text  GET /events?after=<last id>&wait=20
								576 text ; the call returns as soon as there is something (up to 100 events), or after about 20 seconds with an empty list. The SDK runs that loop for you. Events come in order and each id once; if a poll fails, ask again with the same 
								577 text after
								578 text  and nothing is lost. (A bot that was offline for a while skips slash commands older than 15 minutes and button clicks that already expired, see 
								579 text /events
								580 text  below.) No public URL, no port forwarding, works on a laptop behind any router. If you do host the bot somewhere, set a webhook URL in Settings → Developer → your bot → Advanced and the same events are also POSTed there (see Event webhooks). Messages people send in DMs aren't sent to bots as events. A bot can still open a DM and post there.
								581 heading Gateway (beta), Value: 3
									582 text Gateway (beta)
								583 text Instead of polling, a bot can keep one WebSocket open and get its events pushed, like Discord's gateway. Same events, same ids, same order as 
								584 text GET /events
								585 text , so switching changes nothing in your handlers. It's in beta: bots not in it yet get closed with code 4003, so just keep polling then. Both SDKs do all of this for you (yapper.js on Node 22+, Bun and Deno; yapper.py 1.1+ on any Python 3.9+, still nothing to install) and fall back to polling by themselves. CODE
