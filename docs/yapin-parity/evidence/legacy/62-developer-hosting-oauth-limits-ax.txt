								40 heading How it works, Value: 2
									41 text How it works
								42 text Yapin’ keeps every event for your bot for a day: new messages in its servers, joins, leaves, reactions, button clicks, voice joins and leaves, tests. Your bot asks
								43 text  GET /events?after=<last id>&wait=20
								44 text ; the call returns as soon as there is something (up to 100 events), or after about 20 seconds with an empty list. The SDK runs that loop for you. Events come in order and each id once; if a poll fails, ask again with the same 
								45 text after
								46 text  and nothing is lost. (A bot that was offline for a while skips slash commands older than 15 minutes and button clicks that already expired, see 
								47 text /events
								48 text  below.) No public URL, no port forwarding, works on a laptop behind any router. If you do host the bot somewhere, set a webhook URL in Settings → Developer → your bot → Advanced and the same events are also POSTed there (see Event webhooks). Messages people send in DMs aren't sent to bots as events. A bot can still open a DM and post there.
								49 heading Gateway (beta), Value: 3
									50 text Gateway (beta)
								51 text Instead of polling, a bot can keep one WebSocket open and get its events pushed, like Discord's gateway. Same events, same ids, same order as 
								52 text GET /events
								53 text , so switching changes nothing in your handlers. It's in beta: bots not in it yet get closed with code 4003, so just keep polling then. Both SDKs do all of this for you (yapper.js on Node 22+, Bun and Deno; yapper.py 1.1+ on any Python 3.9+, still nothing to install) and fall back to polling by themselves. CODE

								118 heading Publishing and verified bots, Value: 2
									119 text Publishing and verified bots
								120 text Your bot works in your own servers from the start. To let  other  servers add it, write a description (20 to 300 characters) and press  Publish for review  on the Community tab in Settings → Developer → your bot. Yapin’ checks every bot by hand (Yapin’ Plus members are checked first). Once approved it's a  verified bot : it appears in Server settings → Bots → Community bots and on 
								121 link /bots, Value: yapin.gg/bots
								122 text , and anyone with Manage Server can add it. If it is sent back you see why, fix it and submit again. Verified bots get a   BOT  tag in chat, can show a support server, can send 300 messages a minute overall instead of 30 (see 
								123 link Limits, Value: yapin.gg/developers#limits
								124 text ) and can use 
								125 link Bot hosting, Value: yapin.gg/developers#hosting
								126 text . Private verification.  Made for one server or one community? On the same Community tab press  Ask for private verification  instead of publishing (it needs the same description). Yapin’ checks it the same way. Once approved it is verified, with the tag, the higher message limit and hosting, but it is not listed anywhere: it stays off 
								127 link /bots, Value: yapin.gg/bots
								128 text  and Community bots. Anyone who has its bot ID and Manage Server can add it from Server settings → Bots →  Have a bot ID? , so treat the ID like an invite link. A verified public bot can go private and keep its tag with  Make private (keep ✓) . Publishing a private bot sends it back for a public review, and the tag and hosting pause until it is approved. Getting into your first servers.  Before Yapin’ verifies a bot it has to be in 3 servers you don't own, with 3+ members each. You don't need roles in other people's servers for that: on the Community tab press  Let server owners add it  and send them its bot ID. Anyone with Manage Server can add it from Server settings → Bots →  Have a bot ID? , up to 10 servers until it is verified. Press  Stop sharing  to turn it off; servers that already have it keep it. Please don't DM people you don't know to ask, post it in a bot promo channel instead.
								129 heading Permissions, Value: 2
									130 text Permissions
								131 text A bot is a member. Everything it does beyond reading and posting is checked with the bot's own roles, the same way as for a person: give the bot a role with  Manage messages  and it can delete and pin,  Manage roles  and it can hand out roles,  Kick ,  Ban ,  Timeout ,  Manage channels ,  Manage nicknames ,  Move Members  likewise. Server settings → Members → the bot → roles. Without a role it can read, post, react and DM.

Without  Speak , or while a mod has it muted, it joins muted. It can't hear anyone, can't share video, and can only be in one voice channel per server (joining another one leaves the first). People see it in the call with a BOT tag. Mods can mute or disconnect it like anyone, but not move it. Up to 10 joins and leaves a minute per bot. The bot also gets
