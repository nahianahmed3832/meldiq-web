# Meldiq default and canonical mascot correction

4 November 2026, Asia/Shanghai. This follows Part 2 source `4da13d6` and implements the owner's correction: Meldiq is the default color theme, and branded logo/emoji use the current mascot.

**Meldiq** (charcoal and lime) is now the default palette in preferences, the static document and the first-paint bootstrap. Unchosen legacy Midnight defaults migrate to Meldiq. Explicit Midnight and other existing palette choices remain intact, including reload/first-paint behavior. Theme brightness remains a separate System/Light/Dark/Black preference.

The canonical character is the owner's [teal-and-cream Meldling](../../../brand/meldling.png), already identified by the owning brand brief and asset generator. `MELDLING_ASSETS` is shared by BrandMark, MeldlingArt and the new MeldlingExpression. Welcome, Home/status illustrations and social-preview metadata now use that same mascot. Illustrated alternate bear posters remain retained source material; active shared UI no longer selects them.

**Google and Discord login are preserved**, including their official icons and existing OAuth handlers. None of `SocialSignIn`, the auth chooser, social-auth implementation or provider icon files was changed by this correction. Local test servers omit unconfigured providers. A separate configured-provider UI fixture verifies both buttons and both existing start handlers; it deliberately returns an outage instead of completing an external OAuth agreement. Both desktop and phone-width cases pass. The first assertion incorrectly expected the raw synthetic 503 message; it was corrected to the client’s existing safe generic error. No auth implementation change was needed. This is UI/handler regression evidence, not real provider-consent evidence.

Built-in stickers and the supported animated emoji use Meldling with a small meaning symbol. The Meldling emoji section appears before the ordinary Unicode catalog, so it is immediately visible. Picker previews and sent messages use the same renderer, with existing captions, accessible names, animation preferences and reduced motion. Community-uploaded artwork and ordinary Unicode messages retain their original meaning and ownership. Wire references, catalog IDs, fallback text and server/native protocols are unchanged; older clients can continue rendering their supported presentation. Part 4 should carry this branded rendering/default choice into native clients when accepting their release.

Validation: full Web unit suite **973 passed / 1 skipped**; initial built-browser scope **7 passed / 1 desktop-only skip** across desktop and phone widths, covering defaults, migration, explicit choice persistence, actual sticker/animated-emoji delivery, ordinary emoji insertion and fresh onboarding. After moving the branded section to the top, its final visibility/delivery and the existing sticker/composer case were repeated: **3 passed / 1 expected phone skip**. The separate Google/Discord provider-entry guard passes on both projects, bringing the unique passed browser cases to **9**, with one expected desktop-only case skipped on phone. Lint, typecheck, full formatting, localization and normal release build pass. No backend, dependency, production configuration or deployment change was made. See [receipt and source hashes](branding/validation.json).
