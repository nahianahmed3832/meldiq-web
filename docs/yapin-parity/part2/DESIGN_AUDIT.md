# Part 2 design audit and system

Date: 4 November 2026, Asia/Shanghai. Scope: the active-release-derived Web source plus isolated local browser fixtures; public site observations are separately labelled. The reference is the retained Part 1 evidence, not newly copied competitor UI. The starting release already had a token system, scoped settings catalog, native-aligned phone tabs, unsaved-change guards, and shared overlays. This pass extends those foundations rather than replacing working domain behavior.

## Original Meldiq system

Use `src/styles/tokens.css` as the canonical scale: Plus Jakarta Sans with system fallback; body 14px and stepped 12/13/15/17/20/26px roles; 4/8/12/16/20/24/32px spacing; control/card/dialog radii 10/18/24px; neutral content surfaces and branded frame. Existing Midnight navy/charcoal with cyan/blue/violet and Plum accents remain. Theme and palette are separate preferences, available freely. No competitor fonts, illustrations, assets, sounds, code or copy were imported.

`src/styles/foundation.css` adds semantic field/focus/reading aliases, password wrapper, three-step progress, asynchronous StatePanel, responsive welcome, section list, home actions, and skip control. Buttons, inputs, selectors, cards, tooltip/notification styles, and shared overlays continue to use the existing canonical classes and tokens. Lucide icon sizes follow the existing 16/18/20px roles; icons supplement visible names. The supplied Meldling artwork anchors the welcome story.

Use primary buttons for one forward/save action, secondary for optional actions, ghost for subordinate navigation; label destructive operations explicitly and keep their existing confirmation contract. Toggle and radio semantics reflect actual persisted state. A disabled control must communicate a real pending operation, invalid input or capability boundary. Empty results are distinct from loading and errors. Domain owners provide retry behavior; StatePanel invents no backend status.

Motion uses the existing 90/120/200/260ms scale. The new loading animation stops for system reduced motion or the existing explicit reduced-motion preference. Keyboard focus remains visible. Menus/dialogs isolate only the top branch and restore focus; individual feature owners must still provide a meaningful trigger, initial focus, accessible name and dismissal behavior.

## Reference comparison and responsive review

Compared retained [Yapin profile reference](../screenshots/current/02-profile.jpg) and [appearance reference](../screenshots/current/04-appearance.jpg) with the actual local [Meldiq welcome](screenshots/welcome-chromium.jpg) and [phone profile sections](screenshots/profile-phone-width.jpg). Applied principles: one settings search, grouped fields, nearby preview, explicit save boundary, understandable section order/visibility, and quick visual appearance choices. Meldiq keeps its own colors, mascot, six canonical palettes, free options, profile fields, privacy controls, account security and destinations. There is no pixel-copy or claim that reference UI proves backend behavior.

Automated target sizes: desktop 1920×1080, 1440×900, laptop 1280×800 and 1024×768, tablet 768×1024, phone 390×844 and landscape 844×390. Phone emulation is not a physical-device check. Welcome stacks into one scrollable column, preference choices wrap, safe-area padding applies, and Home actions fill the available width. Existing settings switch from desktop window to mobile pages and community sheets. Existing phone tabs and focused-chat back behavior remain native-aligned. The new skip control deliberately avoids hidden desktop content. Browser screenshot pixel dimensions can be larger than CSS dimensions because phone emulation uses device pixel ratio.

Physical keyboard overlap, device safe areas, screen-reader interaction, external provider consent and installed Android/Windows acceptance remain separate evidence requirements. Passing browser geometry checks does not certify every palette/color combination to WCAG or constitute a native-device release.
