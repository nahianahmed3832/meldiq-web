# Call identity, connection details, seen receipts and compact navigation

Call tiles and incoming calls now use the authenticated profile-photo component, with initials as the privacy-aware fallback. The signal control reveals current WebRTC round-trip latency to the media server on hover, keyboard focus or a tap. Missing samples remain “Measuring latency”; reconnecting and ended calls clear their previous measurement. No IP addresses or connection credentials appear in the tooltip. RTT is sampled from the chosen ICE candidate pair, with sender RTCP stats as a fallback, using the SDK's public `getRTCStatsReport` method. See the [LiveKit track reference](https://docs.livekit.io/reference/client-sdk-js/classes/Track.html).

The seen-status regression came from the newer message-collection endpoint selecting changes only by target ID: read controls have an `upTo` boundary and no target. Both MongoDB and SQLite collection pages now reuse the same bounded, public, other-member read-marker query as the legacy history endpoint. Self-only markers and the viewer's own markers remain excluded. The browser can rebuild seen ticks after reload without inventing receipts for unread messages.

Community names and Sparks share a 48px header; the optional cover sits below it at 72px. The separate Spark goal card was replaced by a compact count/progress chip opening the existing Sparks dialog. Lobby/invite rows and desktop channel rows are denser. Touch controls retain 44px targets. The screenshot reference's hierarchy guides the design while using Meldiq's theme and icons.

Validation covers type checking, lint, formatting, all unit tests, real encrypted voice calls and photo decoding in Chromium and WebKit, measured latency, hover/focus behavior, seen boundaries before/after reload and desktop/phone geometry. All browser workflows use normal email signup against disposable local services and the exact release exports.

Publication uses both deployment locks, guarded predecessor checks, archive and file hashes, an offline API module smoke check, health checks and rollback. Only three messaging JavaScript modules are overlaid onto the current media API image; its dependencies, migrations and runtime configuration are preserved. The web package includes the current media-sharing release. An earlier attempt rolled back after comparing environment-array order; semantic name/value comparisons replace that check, while retaining strict configuration checks. No manual account or message-data edits are part of this release.
